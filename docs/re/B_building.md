# B. CYBOR.PRG — BUILD operation, country economy/status, world-map icons

Source: cybor.asm (CYBOR.PRG). Compact dumps used for this analysis are in
`re/dump/*.txt` (generated by `re/fnc2.py NAME...`, which collapses push/call sequences and
annotates `_LANGS+n` string pointers from `re/eng_strings.txt`). Raw FPU constants were read
from the DGROUP image with `re/dgdump.py`.

Conventions: `C` = country record base (`_MECHRECORD + c*236`), `P` = player record
(`_MECHRECORD + 12 + 32*p`). `vault` = long at `P+20` (asm: `[_MECHRECORD+32/+34]` indexed by
`p<<5`). `slot[i]` = short at `C+192+2*i`. All money is 32-bit long. Turbo-C FPU emulation
(`int 37h/38h/3Ah/3Dh`) decoded by hand; all float math is double precision then `FTOL` (truncate).

---------------------------------------------------------------------------------------------------

## 1. Exact building rules

### 1.0 Common gate (`_GET_BUILD` → `_VALIDATOR` → `_TRY_BUILD`)

* The BUILD buttons (bottom button bar, see §3.4) set `_BUTTONCONTROL = _OPCONTROL = op`:
  6 = BUILD CYBORGS, 8 = BUILD FORTIFICATION, 9 = BUILD CAPITAL, 10 = BUILD FACTORY,
  11 = BUILD ENHANCEMENT (op-name strings at `_LANGS+14492 + 25*(op-6)`; 7 is "nothing").
* The player clicks a country on the map (`_GET_COORDS`, map window x 16..305, y 16..142).
  `_VALIDATOR` → `_GET_COUNTRY_NUM` → `_COUNTRY1 = country`, `_CHECK_OWNERSHIP`:
  `_OWNER = (C+172 == _CURPLAY)`. If not owner: "SELECTION CANCELLED. YOU DO NOT OCCUPY THIS
  COUNTRY." (error sound). Otherwise `_TRY_BUILD`.
* `_TRY_BUILD` first calls `_GET_AMOUNT_OF_SPACE` (§1.1). Every build except the capital
  requires `slot[0] == 1` ("YOU MUST ESTABLISH A GOVERNMENT IN THIS COUNTRY BEFORE YOU CAN
  BUILD.").
* Money is **never** checked against anything but the current player's vault; there is no
  per-turn build limit — the op stays active (`_KEEPOP`) so several countries can be built in a
  row, until the player clicks the button bar again.

### 1.1 `_GET_AMOUNT_OF_SPACE` — "SPACE AVAIL" and structure census (for `_COUNTRY1`)

```c
void GET_AMOUNT_OF_SPACE(void) {               // operates on C = country _COUNTRY1
    FREESPACE = FORTFLAG = FORTLEVEL = FACTFLAG = MECHSPACE = BAYSPACE = 0;
    ENHANCENUM = FACTNUM = TONNAGE = 0;
    FORTTYPE[0..3] = "NO FORTIFICATION","LIGHT FORT.","MEDIUM FORT.","HEAVY FORT."; // 25-byte strings
    for (i = 0; i <= C.build_space - 1; i++) {        // C+224 slots, i.e. slot[0..build_space-1]
        if (slot[i] == 0) FREESPACE++;                // empty slot
        if (slot[i] == 2) { FORTFLAG = 1; FORTLEVEL = C.fort_level /*+226*/; }
        if (slot[i] >= 3 && slot[i] <= 6) { FACTFLAG = 1; FACTNUM++; }   // factory codes 3,4,(5),6
        if (slot[i] == 7) ENHANCENUM++;
    }
    for (s = 0; s < 10; s++) {                        // cyborg slots C+234+10*s
        if (cyb[s].type == 10) MECHSPACE++;           // empty cyborg slot
        else if (cyb[s].location == _COUNTRY1) TONNAGE += _HL[cyb[s].type];  // _HL = 750,600,390,270,150,150,90,90,30
    }
    for (b = 0; b <= C.factory_potential - 1; b++)    // C+388 bays
        if (bay[b] == 10) BAYSPACE++;                 // empty bay
}
```

So **SPACE AVAIL = FREESPACE = number of zero entries among the first `C+224` build slots.**
Build space `C+224` is 1 for cities, 7 for the five starting countries, `rand(2,7)` otherwise.
Slot 0 is always the capital; forts/factories/enhancements take the *first empty* slot
(`_FILL_BUILD_AREA(code)`), so a country can hold at most `build_space - 1` non-capital structures
(cities: only a capital, nothing else can ever be built there).

### 1.2 Capital / government (op 9)

```c
if (vault < 30000) { msg "IT WILL COST 30000 TO ESTABLISH A GOVERNMENT. YOU HAVE: %ld  SELECTION CANCELLED."; fail; }
if (slot[0] == 1)  { msg "YOU ALREADY ESTABLISHED GOVERNMENT CONTROL IN <name>  SELECTION CANCELLED."; fail; }
slot[0] = 1;  vault -= 30000;  sound _FLAG;
msg "YOU HAVE ESTABLISHED GOVERNMENT CONTROL IN <name>";
PLOT_FLAG(player, C.x, C.y) on SCREEN3 (world) and on PHYSSCREEN at (x-MAP_X+16, y-MAP_Y+16);
```
Prerequisite is only ownership (`C+172 == player`). Note the capital never occupies a
counted "space" of its own beyond slot 0 (slot 0 is one of the `build_space` slots, so a
country with build_space 2 can hold capital + 1 structure). Capital makes the country produce
income (§2.4) and is required for everything else. (Other agents: `_CLEAR_STRUCT` wipes
slots/forts/bays on conquest.)

### 1.3 Fortifications (op 8) — `_TRY_BUILD` precheck + `_FORT_SEQ`

Tables: `_FORTCOSTS = {100000, 200000, 300000}` (longs, index = level-1).
Level 1 LIGHT "4 LAC - 4 LRM", 2 MEDIUM "4 HAC - 6 LRM", 3 HEAVY "4 NC - 8 LRM".

Precheck in `_TRY_BUILD`:
```c
if (!(FORTFLAG == 1 || FREESPACE > 0)) goto no_room;        // "THERE IS NO ROOM TO BUILD ANYTHING IN THIS COUNTRY."
if (C.fort_level == 3) { msg "THIS COUNTRY IS HEAVILY FORTIFIED. MORE FORTIFICATION IS NOT POSSIBLE."; fail; }
if (vault < _FORTCOSTS[FORTLEVEL]) {        // cost of the NEXT level (index = current level 0..2)
    msg "IT WILL COST AT LEAST %ld TO FORTIFY THIS COUNTRY. YOU HAVE: %ld"; fail; }
FORT_SEQ();
```
`_FORT_SEQ` (menu with three castle buttons, OK, CLEAR):
```c
sel = 0; chosen = -1; TEMPVAULT = vault; TEMPCOUNTRY[0..6] = slot[0..6]; TOTALCOST = 0;   // UP_DATE_FORT(1)
loop {
  click = EVNT_BUTTON();
  if (click in OK   (x 191..208, y 26..45)) {
      slot[0..6] = TEMPCOUNTRY[0..6]; vault = TEMPVAULT;
      if (chosen >= 0) { C.fort_level = sel+1; sound _FORTIF; PLOT_FORT_ICON(sel+1, C.x+19, C.y+4) world+screen; }
      done; }
  if (click in CLEAR(x 98..159, y 25..44))  { UP_DATE_FORT(1) /* resets TEMPVAULT, TEMPCOUNTRY, FORT_SEQ state */; sel=0; chosen=-1; continue; }
  if (click in x 94..116) {                               // the three castle icons
      if (y 46..63)  { sel = 0; BUTTONCONTROL = 12; }     // light
      if (y 68..85)  { sel = 1; BUTTONCONTROL = 17; }     // medium
      if (y 90..112) { sel = 2; BUTTONCONTROL = 18; }     // heavy
      // acceptance test:
      if (_FORTCOSTS[sel] <= TEMPVAULT                    // can afford
          && (FREESPACE > 0 || FORTFLAG == 1)             // room, or already has a fort (upgrade uses no new slot)
          && sel + 1 > FORTLEVEL                          // strictly higher than the existing level
          && sel > chosen) {                              // strictly higher than what was picked this session
          if (vault > TEMPVAULT) TEMPVAULT = vault;       // undo the previously picked level's cost
          TEMPVAULT -= _FORTCOSTS[sel];                   // FULL price of the new level, no credit for the old one
          if (FORTFLAG != 1) { FILL_BUILD_AREA2(2); FORTFLAG = 1; FREESPACE--; }  // writes code 2 into TEMPCOUNTRY
          UP_DATE_FORT(0, sel); chosen = sel;
      }
  }
}
```
Rules: one fortification per country (code 2 occupies one slot); upgrading replaces it
(no extra slot) and costs the full price of the new level; only upward; level 3 is final.
`UP_DATE_FORT` displays VAULT (white if TEMPVAULT ≥ 300000, else dim), "FORT. LEVEL: <FORTTYPE>",
"SPACE AVAIL: FREESPACE". `_FORTLEVEL` is only refreshed by `_GET_AMOUNT_OF_SPACE` (UP_DATE_FORT(1)).

### 1.4 Factories (op 10) — `_TRY_BUILD` precheck + `_FACT_SEQ`

Tables: `_FACTCOST = {500000, 800000, 1200000}`, `_FACTPOT = {1, 2, 4}` (bays),
`_FACTFILL = {3, 4, 6}` (slot code written for uni/dual/quadro — used by HAL's `_LOCATE_FACTORY`;
the human menu hard-codes the same: code = 3 + {0,1,3}).

Precheck: `FREESPACE == 0` → "THERE IS NO ROOM TO BUILD ANYTHING IN THIS COUNTRY.";
`vault < 500000` → "IT WILL COST AT LEAST 500000 TO BUILD ANY TYPE OF FACTORY. YOU HAVE: %ld".

`_FACT_SEQ` (three factory buttons, OK, CLEAR; several factories may be bought per session):
```c
UP_DATE_FACT(1): GET_AMOUNT_OF_SPACE(); FACTBUILD[0]=FACTBUILD[1]=FACTBUILD[3]=0; TEMPFACTP = C.factory_potential;
                 TEMPVAULT = vault; TOTALCOST = 0; TEMPCOUNTRY[0..6] = slot[0..6];
loop {
  OK (x 191..208, y 26..45):
      for i in 0..6: if (TEMPCOUNTRY[i] in 3..6 && slot[i] != TEMPCOUNTRY[i]) { sound _FACTORY; PLOT_FACTORY(player, C.x, C.y, 2) on SCREEN3; }
                     slot[i] = TEMPCOUNTRY[i];
      vault = TEMPVAULT; C.factory_potential (+388) = TEMPFACTP; done;
  CLEAR (x 98..159, y 25..44): UP_DATE_FACT(1); continue;
  factory icon (x 94..116): y 46..63 → k=0 (uni, BUTTONCONTROL 12); y 68..85 → k=1 (dual, 13); y 90..112 → k=3 (quadro, 14)
      cost = {0:500000, 1:800000, 3:1200000}[k];
      if (TOTALCOST + cost <= vault && FREESPACE > 0) {
          TOTALCOST += cost; TEMPVAULT -= cost;
          FILL_BUILD_AREA2(k + 3);           // slot code 3 / 4 / 6 into first empty TEMPCOUNTRY slot
          TEMPFACTP += k + 1;                // +1 / +2 / +4 bays
          FACTBUILD[k]++; FREESPACE--;
          UP_DATE_FACT(0);
      }
}
```
Limits: number of factories per country is bounded only by free build slots (max 6 → max
24 bays = the 24 bay shorts). Bays per country = `C+388` (sum of the factories' bays; "FACTORY
POTENTIAL" in the status box). `_FACTORY_PRESENT`/`_ADD_ENEMY_FORTS` derive bays as
`slot_code - 2` (3→1, 4→2, 5→3, 6→4); code 5 (a "tri-post") exists in drawing/matrix code but is
never purchasable. UP_DATE_FACT shows the three counts bought this session, VAULT (white if
TEMPVAULT ≥ 1200000), TOTAL COST, SPACE AVAIL.

### 1.5 Factory enhancement / upgrade (op 11)

```c
if (FACTFLAG == 0) { msg "A FACTORY UPGRADE CANNOT BE BUILT WITHOUT A FACTORY ESTABLISHED."; fail; }
if (FREESPACE == 0) { msg "THERE IS NO ROOM TO BUILD ANYTHING IN THIS COUNTRY."; fail; }  // checked before FACTFLAG, same as factories
if (vault < 400000) { msg "A FACTROY UPGRADE COSTS: 400000  YOU HAVE: %ld"; fail; }
FILL_BUILD_AREA(7); sound _ENHANCE; msg "FACTORY UPGRADE INSTALLED."; vault -= 400000;
```
No explicit maximum: each enhancement is a slot-code-7 structure, so max = free slots
(≤ 5 with a capital and one factory in a 7-slot country). Effect (`_FILL_IN_MENU`, §1.6):
```c
MFCOST[t] = (long)( UNITCOST[t] * (1.0 - ENHANCENUM / 10.0) );          // -10 % per enhancement (FP, truncated)
MFBT[t]   = max( BUILDTIME[t] - ENHANCENUM, MFBTMIN[t] );               // -1 turn per enhancement, floor MFBTMIN
```
`_BUILDTIME = {5,4,3,3,4,2,1,1,1}`, `_MFBTMIN = {3,2,1,1,2,1,1,1,1}` (= BUILDTIME-2 clipped at 1:
"production time can only be reduced by a maximum of two turns"). `_FACTFILL`/`_FACTPOT` are
*not* involved in build time (they are the factory slot code / bay count tables). With ≥10
enhancements the FP cost would go to 0 or negative — practically unreachable (≤5 slots).
Manual table matches: Titan 100000/90000/80000/…, times 5/4/3/3/3/3.

### 1.6 Cyborg production (op 6) — `_SHOW_CYB_MENU`, `_FILL_IN_MENU`, `_SELECT`, `_RESOLVE_MECHS`

Precheck in `_TRY_BUILD`: `FACTFLAG == 0` → "YOU CAN ONLY BUILD CYBORGS IN A COUNTRY WITH A
FACTORY." Then fade out, `_SHOW_CYB_MENU`, reload framebt3.gif/button10.gif, fade in, and
`PLOT_FACTORY(player, C.x, C.y, BAYSPACE ? 2 : 0)` on SCREEN3 (world map).

```c
// _FILL_IN_MENU(mode)  mode 0 = (re)start session, 1 = redraw only (after a cyborg info screen)
if (!TACTICAL && mode == 0) {
    GET_AMOUNT_OF_SPACE(); TEMPVAULT = vault; TEMPBAY[0..23] = bay[0..23];   // work on copies
} else if (TACTICAL && mode == 0) {           // battle-practice "showdown" purchase (other agent)
    INIT_BAYS(); BAYSPACE = 10; ENHANCENUM = 0; FACTNUM = 10; MECHSPACE = 10; TEMPVAULT = BUYMONEY;
}
CYBBUILT[0..9] = 0; TOTALCOST = 0;
for t in 0..8: MFCOST[t], MFBT[t] as in §1.5; print cost and build time in the 3x3 grid
GET_CYBS_IN_PRODUCTION();   // CYBBUILT[t] = count of TEMPBAY[b] (b < factory_potential) with 0 <= TEMPBAY[b] % 100 <= 8 ; CYBBUILT[9] = total
TOTAL = CYBBUILT[9];
if (MECHSPACE == 0) msg "WARNING: THIS COUNTRY HAS 10 CYBORGS. ALL CYBORGS BUILT WILL STAY IN THE BAYS.";
show "PLAYER %d:", factory_potential (+388), BAYSPACE ("free bays"), MECHSPACE ("space avail" = empty cyborg slots), TEMPVAULT, TOTALCOST
```
```c
// _SELECT(t)  — click on stats box t (rect _SLX[t])
if (TEMPVAULT - MFCOST[t] < 0) { msg "YOU CANNOT AFFORD THIS CYBORG. SELECTION CANCELLED."; return; }
if (BAYSPACE == 0)             { msg "ALL FACTORY BAYS UTILIZED."; return; }                  // "FACTORY MAX"
INSERT_BAY( MFBT[t] * 100 + t );       // first TEMPBAY[b]==10 with b < factory_potential
BAYSPACE--; TOTALCOST += MFCOST[t]; TEMPVAULT -= MFCOST[t]; TOTAL++; ADD_CYB(t) /* CYBBUILT[t]++ and redraw */;
```
```c
// OK button (x 241..304, y 11..29):  (TACTICAL variant uses RESOLVE_MECHS2 / BUYMONEY)
RESOLVE_MECHS(): vault = TEMPVAULT; bay[0..23] = TEMPBAY[0..23];  CYBCHOICE = BUILDCHOICE = 1; leave menu
// CLEAR button (x 12..75, y 11..29): FILL_IN_MENU(0)  -> discards all selections of this session
// click on picture box _PLX[t] -> LOAD_DISPLAY_CYB(t) (info screen), returns via FILL_IN_MENU(1)
```
**Bay encoding**: `bay = turns_left*100 + type` (type 0..8). 10 = EMPTY bay. Examples:
104 = CROSSBOLT (4) with 1 turn left, 302 = HERCULES (2) with 3 turns left, 7 = finished
CYCLOPS waiting for a free cyborg slot. A cyborg can never be built with 0 turns: MFBT ≥ 1, so a
fresh purchase is ≥ 100. Only bays `0 .. factory_potential-1` are ever used.

**Per-turn processing** (`_INC_DATE`, turn-flow agent's scope, summarised for the bay semantics):
```c
for each country c owned (owner != 5):
    for b in 0..23: if (bay[b] >= 100) bay[b] -= 100;                 // one turn of construction
    ...income (see §2.4)...
    C.cyborgs (+228) = number of cyborg slots with type != 10;
    for (b = 0; C.cyborgs < 10 && b <= 23; b++)
        if (bay[b] < 100 && bay[b] != 10)                             // finished cyborg
            for first free slot s (type == 10): cyb[s].type = bay[b]; cyb[s].status = 100; cyb[s].location = c;
                                                 bay[b] = 10; C.cyborgs++;
```
Hence "the country already has 10 cyborgs": production continues, finished cyborgs sit in
their bay (value 0..8) and keep the bay occupied (BAYSPACE counts only `== 10`), delivered one per
free slot on later turns. `_BAY_LIST` shows such bays as "<name> R" (ready) and empty bays as
"EMPTY BAY", others as "<name> <turns>" with turns = bay/100 (1..5).

`_BUYMATRIX` is **not** used by the human build path. It is HAL's shopping list: 12 rows × 21
shorts (row = `[_MECHRECORD+17646]`, a HAL phase index set in `_GAME_INIT`), entries [0..19] are
purchase codes, [20] = remaining count (`_HAL_BUYS`, HAL agent's scope).

### 1.7 Money deduction summary

| action | check | deduction | where |
|---|---|---|---|
| capital | vault ≥ 30000 | vault −= 30000 | `_TRY_BUILD` (immediate) |
| fortification L | TEMPVAULT ≥ `_FORTCOSTS[L-1]` | vault = TEMPVAULT at OK (full price, no upgrade credit) | `_FORT_SEQ` |
| factory | TOTALCOST+cost ≤ vault, FREESPACE>0 | vault = TEMPVAULT at OK (sum of all bought) | `_FACT_SEQ` |
| enhancement | vault ≥ 400000 | vault −= 400000 | `_TRY_BUILD` (immediate) |
| cyborg | TEMPVAULT ≥ MFCOST[t], BAYSPACE>0 | vault = TEMPVAULT at OK | `_RESOLVE_MECHS` |

Starting vault (`_GAME_INIT`): `0x00127690 = 1,209,968`.

### 2.4 Economy numbers (status box / income)

* **NETWORTH** (status box and hover panel) = `(long)( value * ((100 - damage)/100.0) * 1000.0 )`;
  0 if damage == 100. (Both `_SHOW_COUNTRY_STATUS` and `_SHOW_CTRY_STUFF`: FILD value; FILD damage;
  FSUBR 100; FDIV 100; FMULP; FMUL 1000.)
* **Income per turn** (`_INC_DATE`, for every country with `slot[0]==1` and damage != 100):
  `vault[owner] += (long)( value * ((100 - damage)/100.0) * 1000.0 )` — i.e. NETWORTH is the
  per-turn income; an undamaged country yields `value*1000` (poor planet 3000..10000, cities
  10000..30000 — matches the manual's "Planet Type Value Range Table").
* **TONNAGE** = Σ `_HL[type]` of cyborgs located in the country; `_HL = {750,600,390,270,150,150,90,90,30}`.
* **CYBORGS** (hover) = count of slots with type != 10 and location == this country.

## 3. World-map drawing model

Screens: `_SCREEN1` = BUTTON10.GIF sheet (320×200, also holds the fonts), `_SCREEN2` = DOOR3.GIF
(large font / door parts), `_SCREEN3` = the scrolling world map (640×400 composite),
`_LOGSCREEN` back buffer, `_PHYSSCREEN` VGA (320×200). `_DO_BLIT(src, dst, x1,y1,x2,y2, dx,dy, mode)`:
mode 0 copy, 3 copy with transparent colour (button art), 7 icon blit used together with
`_DO_MASK` (which is a 5-byte stub = no-op in the DOS build, so masks do nothing), 15 misc.
`_PRINTN(str, x, y, screen, style)`: style 0 = bright, 1 = normal (font row +5), 2 = large font
from SCREEN2, 3 = small font; glyphs come from BUTTON10 (letters at x=48+4*(c-'A'), y=69/70..73,
digits 1-9 at x=79+4*(c-'1'), '0' at x=115, y=168..172; advance 4 px, 2 px for space/'.').

### 3.1 Map window and coordinates

* `_DMAP` copies SCREEN3 rect `(MAP_X, MAP_Y)..(MAP_X+287, MAP_Y+125)` to the log screen at
  (16,16) (in two pieces); visible map window = x 16..303, y 16..141 (hit-test uses 16 < x < 305,
  16 < y < 142). World coordinate of a click = `mouse + MAP_{X,Y} - 16`.
* A country icon's origin is `(C.x, C.y)` (`+230/+232`). Country hit box used by
  `_CHECK_BUTTON` hover: `C.x-8 ≤ wx ≤ C.x+25`, `C.y-8 ≤ wy ≤ C.y+25`; the highest-numbered
  matching country wins.
* Every icon plotter takes `(player/level, x, y, screen struct[16 bytes], [country], clip)`.
  With `clip != 0` the icon is clipped to the window x 16..303 / y 16..141 (icons on the physical
  screen); with `clip == 0` it is drawn unclipped on SCREEN3 at world coords. The physical-screen
  position is `(x - MAP_X + 16, y - MAP_Y + 16)`.

### 3.2 `_FILL_MAP` — what is drawn per country (c = 1..72, `_MAPFILLARRAY[c]` = owner colour, 5 = skip)

```
if MAPFILLARRAY[c] != 5:
   fog = [_MECHRECORD+17648]; visible = !fog || C.owner == CURPLAY
   if visible && C.battle_flag (+392) < 5:  PLOT_EXPLODE(C.battle_flag, C.x+16, C.y)          // battle marker, attacker colour
   if slot[0] == 1:                                                                             // has capital
       f = FACTORY_PRESENT(c)   // 0 none, 1 factory with no empty bay, 2 factory with an empty bay
       if f && visible: PLOT_FACTORY(owner, C.x, C.y, f)      else: PLOT_FLAG(owner, C.x, C.y)   // under fog enemies always show a flag
```

## 5. Open questions

1. Cyborg slot fields `+6` and `+8` (of the 5-short slot) are not touched by any build/status
   code — likely move/repair state (move agent). `+382` and `+394` are never referenced in CYBOR.
2. `_PLOT_FACTORY` computes bay-grid offsets from its `country` argument (`14+47*((c-1)%6)`,
   `16*((c-1)/6)`) and takes a `state` (1 = full, 2 = free bay) but the final blit ignores both —
   confirm in the Atari/ST original whether factories showed a busy/idle variant; the DOS build
   draws one icon per player colour.
3. `_DO_MASK` is a stub in this build; the `*_MASK` buffers are unused (fine for the port).
4. Slot code 5 (3-bay factory) is drawn/placed but not purchasable by humans; check whether HAL
   (`_LOCATE_FACTORY` uses `_FACTFILL = {3,4,6}`) can ever create it — appears not.
5. `_C` / `_E` rectangle tables: no symbolic reference; resolve from the showdown/unit-fill code
   (other agent) if needed.
6. Enhancement count has no explicit cap; the cost formula becomes ≤ 0 at 10 enhancements, which
   cannot happen with ≤ 7 slots. The Rust port should still clamp cost at ≥ 0.
7. Capital rule nuance: the capital check is `slot[0] == 1`; `_CLEAR_STRUCT` (conquest) zeroes
   all 7 slots, fort level and bays, so a conquered country must be re-capitalised. `_ADJUST_DATA_STRUCT`
   (battle result) degrades a factory slot by `n` bays (code −= n, dropped to 0 if ≤ 2) and
   `+388 −= n`, or deletes an enhancement — detail belongs to the battle-resolution agent.
8. `_FILL_MAP` draws from `_MAPFILLARRAY[c]` rather than `C+172`; the two should be identical
   except where the turn-flow code deliberately hides owners (fog). Verify who fills `_MAPFILLARRAY`.
